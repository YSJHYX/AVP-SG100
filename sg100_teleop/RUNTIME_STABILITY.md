# 长会话运行与资源管理

实时遥操作不再保留未使用的 AVP 全量跟踪历史；最新帧、校准、映射和控制流程保持原有接口。直接使用 `VisionProStreamer(record=True)` 的离线脚本仍可获取完整跟踪历史。

RM65 runner 只在 `--collect-arm-hand-data` 开启时保留已发送命令事件。实时控制发送、最新命令快照和反馈读取与该录制开关独立；直接使用后端的调用方仍默认保留命令事件。

MuJoCo 状态与内置因果 collector 使用会话目录中的磁盘暂存文件，避免 Python 列表、去重集合、事件字典随会话时长占用越来越多 RAM。结束时依然生成原有 NPZ、JSONL 和 manifest，不截断样本，不改变时间戳、关节角度域或数据字段。应为录制目录保留足够磁盘空间；临时文件不是可恢复的正式录制，正常完成前不要删除它们。

本地 viewer 默认最多每秒同步 60 次，可用 `--viewer-hz` 调整；物理步长、跟踪频率和机器人控制频率独立。`--stream-hz` 同时用于快照更新与 AVP 状态发送。发送只保留一个待处理状态，WebRTC 缓冲超过 1 MiB 时跳过旧的可视化快照，拥塞解除后恢复最新状态。机器人命令和录制样本不经过该丢帧路径。

首次连接的每个等待阶段默认最多 30 秒，可用 `--connection-timeout 120` 等方式延长。房间码模式运行期的重连在后台进行，`get_latest()` 不等待网络；既有的帧新鲜度检查继续处理陈旧数据。关闭 streamer 会取消连接等待和 gRPC 接收，重复重连不会不断创建信令线程。

实时 runner 的硬件错误日志由后台线程写入和同步磁盘。正常情况下保留全部结构化记录；磁盘长时间阻塞导致队列溢出时，统计丢弃条数，尽可能在文件尾写入 `DIAGNOSTIC_LOG_INCOMPLETE`，并在退出时报告日志未完整保存。诊断队列不允许拖住机器人控制线程。库中 `RealHardwareErrorRecorder` 默认仍为同步写入；只有显式 `background=True` 才启用该行为。

这些更改不改变启动位姿、增益、限位、C/A/D/E 按键含义和现有安全门。原生 SDK 或显示驱动内部的阻塞仍需要现场观测；不能通过强行取消正在运行的原生调用来保证控制安全。

离线回归使用模拟控制器、合成帧、CPU 状态采样和本机回环通信，不连接机器人，不启动 viewer。
