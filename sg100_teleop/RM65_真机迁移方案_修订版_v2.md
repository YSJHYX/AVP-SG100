# RM65 真机迁移方案（修订版 v2）

> 本文档基于当前 `VisionProTeleop` MuJoCo 仿真链路，对原《RM65 真机迁移方案（sim → real）》进行安全性与控制架构修订。  
> 目标：在**不改动现有 AVP tracking → mapper → TCP filter → 官方 IK 主链**的前提下，引入 RM65 真机后端、真机安全层、实时反馈与 digital twin。  
> 本文只覆盖**实体 RM65-B 控制接入**；实体 SG100 驱动仍不在当前范围内。

写作时间：2026-08-27

---

## 0. 一句话结论

当前主架构可以保留：

```text
AVP tracking
→ TrackingFrameGate
→ AVPWristRelativeMapper
→ TcpTargetFilter
→ RM65IKSolver
→ q_arm_goal
```

但真机侧不应简单做：

```text
q_arm_goal
→ joint-step clamp
→ 100 Hz sender
→ rm_movej_canfd
```

而应升级为：

```text
q_arm_goal
→ IK continuity gate
→ latest-target buffer
→ RealJointTrajectorySafetyLimiter
   ├─ joint position limit
   ├─ joint velocity limit
   └─ joint acceleration limit
→ fixed-period sender
→ rm_movej_canfd
→ RM65

RM65 realtime feedback
→ SafetyMonitor
→ digital twin / recorder / AVP
```

# 1. 当前主链与迁移边界

## 1.1 当前 sim-only 链路

```text
AVP 右手 tracking (~60 Hz)
  → TrackingFrameGate
  → AVPWristRelativeMapper
  → TcpTargetFilter
      τ_position = 0.06 s
      τ_rotation = 0.06 s
      max_linear_velocity = 0.25 m/s
      max_angular_velocity = 1.5 rad/s
  → RM65IKSolver
  → q_arm_goal
  → MuJoCo arm command path
  → data.ctrl
  → MuJoCo physics
```

迁移到实体 RM65 后，上游全部继续复用。

## 1.2 真机迁移的核心插入点

现有单点出口：

```text
write_robot_controls()
```

真机迁移应在该层附近引入 backend abstraction：

```text
                    ┌─ SimArmBackend
q_arm_cmd ──────────┤
                    └─ RM65RealBackend
```

不应把 RealMan SDK 调用散落到 mapper、filter、IK、arming、recorder、AVP streaming 等模块中。

# 3. 必须修正的关键设计决策

## 3.1 `rm_movej_canfd` 的 follow / trajectory mode 语义

原方案中的：

```text
follow=False
trajectory_mode=2
```

不应作为固定起步组合。

建议显式定义三种模式：

### Low-follow

```text
follow = False
trajectory_mode = 0
```

用途：最初链路联调、低风险验证。

### Filtered high-follow

```text
follow = True
trajectory_mode = 2
radio = tuned value
```

用途：真机遥操作首选稳定模式，控制器侧再做一层滤波。

### Raw high-follow

```text
follow = True
trajectory_mode = 0
```

用途：后续低延迟实验，仅在 sender 周期稳定、安全层完整后开启。

建议 CLI：

```text
--arm-follow low
--arm-follow filter
--arm-follow high
```

不要把 `follow=False + mode=2` 作为“低跟随滤波模式”。

---

## 3.2 高跟随 sender 不建议仅做 100 Hz

如果高跟随要求周期不超过 10 ms，则：

```text
100 Hz = 10 ms
```

没有 jitter 余量。

建议：

```text
LOW / initial:
100 Hz

HIGH-FOLLOW later:
125 Hz 或 200 Hz
```

实际运行必须测：

```text
mean period
p95 period
p99 period
max period
missed deadline count
```

# 4. 真机 feedback：优先 realtime push，不以 50 Hz TCP polling 为主

原设计：

```text
CANFD sender ~100 Hz
+
rm_get_current_arm_state() polling ~50 Hz
```

可以作为 fallback，但不建议作为 production 主路径。

建议 real backend 设计为：

```text
RM_TRIPLE_MODE_E
+
UDP realtime state callback
```

目标结构：

```text
TCP command channel:
q_arm_cmd
→ rm_movej_canfd()

UDP realtime feedback:
RM65
→ callback
→ ArmState buffer
```

优点：

- 避免 command 与 polling 长期争用 TCP 调用链
- feedback latency 更低
- digital twin 更稳定
- safety watchdog 更可靠
- 后续真机数据采集更自然

TCP polling 可保留作 startup verification / diagnostic fallback。

# 5. Backend 接口需要比 `joint_state() -> q_rad` 更完整

建议定义：

```python
@dataclass
class ArmState:
    q_rad: np.ndarray
    qd_rad_s: np.ndarray | None
    received_monotonic_ns: int
    sequence: int
    controller_error: int | None
    arm_status: int | None
    valid: bool
```

目标发送至少包含：

```python
@dataclass
class ArmTarget:
    q_rad: np.ndarray
    source_timestamp_ns: int
    sequence: int
```

原因：latest-target sender 必须知道当前 target 是真的最新，还是线程在重复发送一个已经过期的旧目标。

---

# 6. 真机 command filter 不能继续使用 MuJoCo 500 Hz dt

仿真中的：

```text
physics timestep = 0.002 s
500 Hz
```

不能作为真机 command conditioner 的 dt。

真机应独立实现：

```text
RealJointTrajectorySafetyLimiter
```

使用：

```python
time.monotonic_ns()
```

计算 sender 实际 dt。

结构：

```text
AVP / IK ~60 Hz
    ↓
latest target
    ↓
real sender 100/125/200 Hz
    ↓
conditioner with actual dt
    ↓
CANFD
```

---

# 7. Joint-step clamp 不足，至少要限制 q / qdot / qddot

CANFD pass-through 不做传统完整轨迹规划，因此软件侧安全层至少需要：

## 7.1 Joint position limits

```text
q_min + safety_margin
≤ q_cmd
≤ q_max - safety_margin
```

## 7.2 Joint velocity limits

```text
|qdot_cmd| ≤ qdot_max
```

离散形式：

```text
|q_cmd[k] - q_cmd[k-1]|
≤ qdot_max * dt
```

## 7.3 Joint acceleration limits

```text
|qddot_cmd| ≤ qddot_max
```

离散形式：

```text
|qdot_cmd[k] - qdot_cmd[k-1]|
≤ qddot_max * dt
```

第一版不强制 jerk-limited OTG，但至少必须有 position + velocity + acceleration 三层约束。

---

# 8. IK branch jump 不能只靠 clamp

危险例子：

```text
previous:
J4 = +20°

new IK branch:
J4 = -150°
```

如果只做 `±Δq clamp`，机器人可能逐渐向错误 branch 移动。

正确顺序：

```text
IK candidate
    ↓
joint limits valid?
    ↓
distance to previous seed acceptable?
    ↓
branch continuity acceptable?
    ↓
YES → trajectory limiter
NO  → reject + hold
```

建议新增：

```text
IKContinuityGate
```

异常 branch：

```text
REJECT
HOLD CURRENT
RE-SEED FROM ACTUAL FEEDBACK
```

而不是 clamp toward bad solution。

---

# 9. C calibration 与 ARM enable 必须分离

真机不建议：

```text
按 C
→ calibration
→ 立即允许发送运动
```

建议状态机：

```text
DISCONNECTED
    ↓
CONNECTED_SAFE
    ↓
SYNCED
    ↓
CALIBRATED
    ↓
ARMED
    ↓
RUNNING
```

语义：

```text
C:
只执行 anchor / calibration

ARM:
单独动作，才允许真实运动指令进入 sender
```

---

# 10. C anchor 应使用实际 joint feedback + software FK

不建议依赖 controller 当前 tool frame 的 pose 作为唯一 anchor。

推荐：

```text
real joint feedback q_actual
        ↓
same software FK used by project
        ↓
canonical TCP pose
        ↓
wrist_mapper.calibrate()
```

这样 sim/real 共享同一个 TCP definition。

# 12. “MuJoCo world = RM65 base”不能扩大解释到真实工位

已经验证的 robot base frame 一致性，只说明机器人运动学 frame 一致。

不能直接推出：

```text
simulation table pose
=
physical table pose
```

真机安装后仍必须重新测：

```text
T_base_table
```

至少记录：

```text
table height
front boundary
back boundary
left boundary
right boundary
```

# 13. Electronic Fence 建议做双层

## Layer 1 — Software workspace guard

PC 侧先检查 desired / actual TCP 是否在允许空间。

## Layer 2 — Controller electronic fence

控制器侧作为最后防线。

建议 whole-arm effective region。

同时必须在真机上单独验证：

```text
electronic fence
+
rm_movej_canfd
```

的实际触发行为。

---

# 14. Collision API 职责必须区分

不要把：

```text
rm_set_collision_detection()
```

写成动态碰撞灵敏度。

建议区分：

## Dynamic collision protection

```text
rm_set_collision_state(stage)
```

## Optional static collision detection

```text
rm_set_collision_detection(enable)
```

Phase 3 中应分别配置与验证。

---

# 15. Tracking timeout 必须缩短到真机安全量级

建议至少两个 watchdog：

```text
TargetAgeWatchdog
FeedbackAgeWatchdog
```

第一版可从：

```text
100 ~ 200 ms
```

量级测试。

### Target stale

```text
latest target age > threshold
→ rm_set_arm_slow_stop()
→ sender disable
→ DISARM
```

### Feedback stale

```text
feedback age > threshold
→ rm_set_arm_slow_stop()
→ sender disable
→ DISARM
```

恢复后：

```text
clear stale target
read actual q
reset limiter
reset IK seed
re-calibrate
re-arm
```

禁止自动恢复 RUNNING。

---

# 16. “停止发送即慢停”不能作为控制器保证

production 不能依赖：

```text
sender stops
→ robot automatically slow-stops
```

正确 watchdog 语义：

```text
detect starvation / stale target
        ↓
rm_set_arm_slow_stop()
        ↓
disable sender
        ↓
DISARM
```

必要时：

```text
rm_set_arm_stop()
```

物理急停按钮仍是独立最高安全层。

---

# 17. Digital Twin 不应简单周期性强写 qpos + mj_step

若一边 `mj_step @500 Hz`，一边周期性覆盖 arm qpos，可能造成 contact / actuator discontinuity。

建议第一阶段：

```text
Real arm:
feedback-driven kinematic twin

Sim hand:
independent simulated hand state
```

视觉 MjData：

```text
write actual arm q
write simulated hand q
mj_forward
```

arm digital twin 先不让 MuJoCo actuator 自己积分。

---

# 18. “10% / 25% / 50%”定义成 software safety profile

CANFD 没有普通 `rm_movej(v%)` 那种速度百分比。

因此定义：

```text
PROFILE_10
PROFILE_25
PROFILE_50
```

作为软件侧安全比例，例如作用于：

```text
qdot_limit
qddot_limit
tcp_limit
```

而不是 controller `v=10/25/50`。

# 29. 风险与缓解（修订）

| 风险 | 缓解 |
|---|---|
| CANFD sender jitter | fixed-period sender + timing metrics；high follow 后期用 125/200 Hz |
| stale target 被重复发送 | target timestamp + seq + watchdog |
| feedback 断流 | feedback-age watchdog → explicit slow stop |
| IK branch switch | continuity gate，reject / hold / reseed |
| q jump | q / qdot / qddot limiter |
| 坐标轴方向错误 | PROFILE_10 + 逐轴实机验证 |
| controller TCP 与软件 TCP 不一致 | actual q + software FK 做 anchor |
| 实际桌面与仿真桌面不一致 | 实测 `T_base_table`，重新生成真实 fence |
| 装 SG100 后安全包络改变 | tool profile |
| CANFD 停发语义不确定 | watchdog 显式调用 slow stop |
| digital twin 瞬移 | real arm 用 feedback-driven kinematic twin |
| collision API 混用 | dynamic / static 两套 API 分开配置 |
| 软件失效 | 独立物理急停 |
