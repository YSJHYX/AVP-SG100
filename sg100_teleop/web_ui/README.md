# AVP-SG100 本机数采工作台

实现基准：远端 `Biyi`，提交 `f7fcc5c171a8218460d1af5a3d62938201fb521d`。
保留原生 MuJoCo 诊断窗口、原有控制参数、手部模式与 30 Hz RAW 数采合同。

## 启动

使用原有 AVP 数采 Python 环境，在项目根目录运行：

```bash
python -m sg100_teleop.web_ui
```

浏览器打开 `http://127.0.0.1:8090`。更换端口可加 `--port 8091`。
打开页面不会连接机器人；点击“准备设备”才会启动相机和控制进程。
首次填写实际 D455、D405 序列号、AVP/RM65 地址和手部串口。
若 SDK 不在原有默认位置，可填写 SDK 目录。

本开发副本可以使用原项目现有虚拟环境：

```bash
cd /data/projects/VisionProTeleop/worktrees/biyi-web-ui
/data/projects/VisionProTeleop/.venv/bin/python -m sg100_teleop.web_ui
```

仅查看交互、验证录制保存流程时使用离线演示：

```bash
/data/projects/VisionProTeleop/.venv/bin/python -m sg100_teleop.web_ui --demo
```

演示使用合成 RGB 与模拟遥测，不连接真实硬件。默认数据写入
`recording/ui-demo/vla_raw`，NPZ 标记 `capture_source=offline_demo`，
`dataset_status=OFFLINE_DEMO_NOT_TRAINING`。禁止使用默认正式 RAW 目录保存演示数据。

## 日常流程

1. 填写工位设置和任务，点击“准备设备”。工位配置会自动保存。
2. 如果勾选“启动时执行回初始位”，本步骤会执行原有 Biyi 启动运动：
   手部初始姿态和机械臂配置初始姿态。启动前确认工作区；该运动早于 C/A。
3. 确认两个 RGB 画面与遥测正常，点击“建立锚点”，等待完成。
4. 点击“启用遥操”，确认初始场景，再点击“开始录制”。
5. 完成任务后点击“结束本条”：撤销运动授权，等待 0.75 秒，结束录制、刷新写入并校验。
6. 使用同步帧滑块或播放按钮检查两路录像；选择是否标记 DAgger，保存或丢弃。
7. 下一条任务前点击“归位并准备下一条”，按提示确认中立姿态并建立新锚点。
8. 完成本轮后点击“关闭本轮设备”。正在录制或等待确认时，需要先处理当前片段。

“仅停止录制”位于单独操作区，保持原有 Off 语义，不代替停止遥操。
“停止遥操”按钮和 D 快捷键在结束操作、刷新写入时仍可使用。
停止未获得控制端确认时，网页会明确报告，不能据此认定机器人已停稳。

### 保持连接：归位并准备下一条

每条保存或丢弃后，点击“归位并准备下一条”，无需关闭/重新准备设备。
流程为：当前数据已处理 → 撤销遥操授权 → 手部初始指令、机械臂预设归位 →
机械臂反馈确认到位 → 提示中立姿态 → 点击“确认中立并建立锚点”（或 C） →
新有效 AVP 帧完成锚点重建 → 等待点击“启用遥操”。不会自动启用或自动开始录制。

归位按钮会执行实际运动。操作前放下物体，并确认预设归位路径畅通。
沿用 Biyi 初始关节姿态、手部初始目标和 25% 规划速度；机械臂运行中使用
`rm_movej(..., block=0)`，保留连接和反馈线程，暂停 CANFD 发送。
到位要求新的有效关节反馈：各轴距离目标不超过 1°、反馈速度不超过 0.05 rad/s，
连续稳定至少 0.2 秒；30 秒超时、控制器错误、反馈丢失会停止归位并报告失败。
手部同时检查串口、故障与 MODE7 回调新鲜度。

由于现有手部 F_fb 仍未完成独立验证，界面明确区分“机械臂反馈已到位”与
“手部初始指令已发送”；确认中立时也请检查手部实际初始姿态，不把发送成功当作
手部物理到位证明。手部映射和训练就绪语义保持不变。

归位中不接受启用遥操、录制、切换手部模式或 C 标定。“停止遥操”/D 可中止
归位，原生 E 会继续执行手部急停锁存。中止后需重新建立锚点才可启用。
归位或新锚点失败不会重新使能，也不会保存、丢弃或覆盖已有 episode。
双相机、录制器、遥测、设备句柄和原生窗口保持原会话。

### 手部模式与快捷键

| 输入 | 功能 |
|---|---|
| 1 / FREE | 自由模式 |
| 2 / HAND | 手形模式 |
| 3 / CLAW | 夹爪模式 |
| 4 / SCRIPT | 脚本控制 |
| 5 / PINCH | 捏取模式 |
| 6 / TWO_FINGER | Biyi 原有联动模式 |
| J / K / L | SCRIPT 模式闭合 / 保持 / 张开 |
| C | 建立锚点 |
| A | 网页为明确“启用”；原生窗口保留原有 ARM/DISARM 切换 |
| D | 停止遥操 |
| I | 丢弃未保存片段并立即重录 |

两处的数字键和页面模式按钮进入同一控制线程，网页根据控制端状态更新选中模式。
输入任务指令、IP、序列号等文本时，网页不响应上述快捷键。
录制中与待确认期间锁定 C，避免坐标重建被混入同一条数据。

### 失败恢复重录

先停止遥操，确认机器人停止，人工复原场景并退出相机画面，再按网页 I 或点击重录。
只删除当前未保存片段；连接、指令、候选编号保持。新片段自动标记 `failure_recovery`。
重新启用遥操后继续任务。DAgger 标签独立选择，沿用原有媒体目录 metadata 合同。

## RGB 与质量显示

两路预览复用 Recorder 相机，不再次打开 USB 相机。
独立线程最多按 12 fps 编码预览 JPEG，并仅保留每路最新帧；正式采集维持 30 Hz，
原有录制 JPEG 质量与 RAW 时间戳不受预览影响。界面标出采集帧率与当前帧年龄。

“设为初始参考”保存当前头部画面。勾选叠加并调整透明度，辅助恢复场景；
叠加仅在网页显示，训练图像仍为原始相机 RGB。

相机 READY 必须有新鲜画面。即使曾收到过帧，过期后也不能开始新录制。
整个 episode 都没有有效 RGB 帧时，质量报告为 FAIL；网页拒绝将 FAIL 候选保存为合格采集。
原生 Recorder CLI 仍可按原有方式保存原始证据。

“已保存 RAW”与“可直接训练”分别显示。现有 F_fb 验证、`training_ready=False`
和 RAW quarantine 语义保持，网页不会改写真实数据的训练资格。

## 进程与文件

- 网页服务仅监听 `127.0.0.1`，不启用重载器。
- Recorder、相机、预览由网页后台单一实例持有；控制端为独立子进程，保留原生窗口。
- 低频命令带有效期和确认回执，磁盘读写在后台 IPC 线程进行。
- 新的停止请求会取消更早排队的启用请求；不会将 A 的切换语义当作网页重试接口。
- 网页刷新或关闭标签页保留后台会话。后台服务退出时先请求停止；控制子进程也检查父进程退出并走设备清理流程。
- 原生 SDK/显示驱动阻塞的行为仍需现场验证；网页停止不是物理急停。

默认工位配置：`recording/ui/station.json`。
控制端日志与 IPC：`recording/ui/sessions/<session-id>/`。
正式数据仍在工位配置的 RAW 目录；原有 MuJoCo 会话日志路径保持。
网页退出不会强制保存尚未确认的数据。
